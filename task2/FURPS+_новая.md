Задание 2. FURPS+ таблица

| Код | Требования                                                                                                                                                                                       | Комментарий                                                                                                        |
|-----|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------|
| F   | Функциональные (Functionality)                                                                                                                                                                   |                                                                                                                    |
| F1  | На сайте новый клиент видит список доступных депозитов с актуальными ставками                                                                                                                    | Ставки должны быть актуальными (Excel - АБС/БД)                                                                    |
| F2  | Клиент на сайте может подать заявку на депозит, указав ФИО и номер телефона                                                                                                                      | Данные передаются в систему кол-центра для последующего звонка                                                     |
| F3  | Менеджер кол-центра видит заявку с сайта в своей системе и может предложить особые условия (после звонка)                                                                                        | Требуется интеграция сайта с системой кол-центра                                                                   |
| F4  | Клиент интернет-банка видит список депозитов с актуальными ставками и персонализированные ставки лично для него                                                                                  | Персонализация требует расчёта на основе данных клиента (скоринг или правила)                                      |
| F5  | Клиент интернет-банка выбирает счёт и сумму депозита, подтверждает операцию СМС-кодом и подаёт заявку                                                                                            | Доработка СМС-функционала силами банка                                                                             |
| F6  | Заявка на депозит (из интернет-банка или сайта) обрабатывается менеджером бэк-офиса депозитов в АБС                                                                                              | Менеджер подтверждает условия и открывает депозит в АБС                                                            |
| F7  | Система отправляет клиенту СМС-уведомления: после подтверждения ставки и после открытия депозита                                                                                                 | Использовать существующий СМС-шлюз                                                                                 |
| F8  | На сайте новый клиент видит предложение кредита (ставка, условия из кредитного конвейера)                                                                                                        | Необходим API от конвейера к сайту                                                                                 |
| F9  | Клиент на сайте подаёт заявку на кредит, указав ФИО и телефон. Если заполнил паспортные данные – система запрашивает решение у скоринга (через БКИ) и возвращает предварительное одобрение/отказ | Для новых клиентов нет данных в АБС, только БКИ                                                                    |
| F10 | После подачи заявки на кредит с сайта клиенту приходит СМС с приглашением прийти в отделение для идентификации и получения кредита                                                               | Использовать существующий СМС-шлюз                                                                                                                   |
| F11 | В интернет-банке клиент видит список кредитов и предодобренное предложение (если есть)                                                                                                           | Предодобрение требует периодического (или по запросу) расчёта скоринга                                             |
| F12 | Клиент интернет-банка подаёт заявку на кредит (по предодобренному или обычному предложению) с указанием счёта зачисления, подтверждает СМС                                                       | Использовать существующий СМС-шлюз                                                                                 |
| F13 | Заявки по предодобренным предложениям обрабатываются сотрудниками бэк-офиса кредитов в течение того же рабочего дня                                                                              | Требуется автоматизация маршрутизации и приоритизации в конвейере                                                  |
| F14 | Клиент получает СМС об изменении статуса заявки на кредит                                                                                                                                        | Заявка должна попадать в кредитный конвейер быстрее, чем раз в сутки (в идеале – онлайн)                                                                                                                   |
| F15 | Сотрудник отделения, работая с клиентом, должен видеть ранее поданную клиентом онлайн-заявку (если есть) и продолжить работу с ней                                                               | Необходимо связывание заявок из разных каналов (единый идентификатор клиента/заявки).                              |
| F16 | По клиентам периодически (например, раз в сутки) должен производиться скоринг для расчёта приемлемой суммы кредита с целью формирования предодобренных предложений                               | Расчёт выполняется асинхронно вне часов пик, например раз в сутки. Результат сохраняется для быстрого отображения  |
| F17 | Незавершённые заявки (без паспортных данных) сохраняются как черновик и доступны сотруднику отделения для дальнейшей обработки                                                                   | Черновик заявки сохраняется в БД с временным идентификатором. При продолжении в отделении – связывается с клиентом |
| U   | Удобство использования (Usability)                                                                                                                                                               |                                                                                                                    |
| U1  | Интерфейс должен соответствовать системе дизайна, которая принята в компании                                                                                                                     |                                                                                                                    |
| U2  | Процесс подачи заявки должен быть интуитивно понятным, с минимальным количеством шагов                                                                                                           |                                                                                                                    |
| U3  | Отклик интерфейса при подаче заявки и расчёте ставки не должен превышать 1 сек                                                                                                                   |                                                                                                                    |
| R   | Надёжность (Reliability)                                                                                                                                                                         |                                                                                                                    |
| R1  | Сервисы интернет-банка должны работать 24/7 и быть доступны в 99,9% случаев                                                                                                                      | Сейчас не выполняется (один ЦОД, нет отказоустойчивости). Нужна репликация/кластеризация                           |
| R2  | В случае сбоя в основном ЦОД необходимо автоматическое переключение на резервный ЦОД без потери данных                                                                                           | Требует синхронизации данных между ЦОД                                                                             |
| R3  | АБС (Oracle) масштабируется только вертикально - нельзя повышать доступность за счёт горизонтального масштабирования. Следует минимизировать прямые вызовы к АБС из интернет-банка               | Архитектурно значимое ограничение                                                                                  |
| R4  | Заявки не должны теряться при сбоях (должна быть гарантия доставки)                                                                                                                              | Рекомендуется использовать очереди сообщений (Kafka) с persistent storage                                          |
| R5  | Система должна обрабатывать дублирующиеся заявки (идемпотентность)                                                                                                                               | Избежать двойной обработки по СМС или повторных кликов                                                             |
| P   | Производительность (Performance)                                                                                                                                                                 |                                                                                                                    |
| P1  | Загрузка справочных данных (ставки, списки продуктов, справочники) — не более ~200 мс                                                                                                            | Устранить проблему долгой загрузки справочных данных (сейчас >1 сек)                                               |
| P2  | Система скоринга не должна перегружаться дополнительными предрасчётами в часы пик; предодобренные предложения лучше рассчитывать асинхронно (например, ночью)                                    | Архитектурное решение - отложенные задачи или очереди                                                              |
| P3  | Выгрузка заявок из АБС в кредитный конвейер раз в сутки – узкое место. Требуется переход на онлайн-обмен (API или Kafka)                                                                         | Ускорит обработку заявок из интернет-банка                                                                         |
| S   | Поддерживаемость (Supportability)                                                                                                                                                                |                                                                                                                    |
| S1  | Необходимо разработать документацию API и архитектурных решений для дальнейшего расширения                                                                                                       |                                                                                                                    |
| S2  | Использовать существующие в банке технологии (MS SQL, Oracle, .NET, Java, Python, PHP), чтобы не увеличивать стек                                                                                | Для новых компонентов допустимы Kafka, но с учётом совместимости                                                   |
| S3  | Реализовать функционал ставок по депозитам централизованно (в АБС или отдельном сервисе), отказаться от Excel                                                                                    | Excel - мавитон                                                                                                    |
| S4  | Избегать доработок СМС-шлюза через подрядчика; использовать существующий API (силами банка)                                                                                                      |                                                                                                                    |
| S5  | Интернет-банк нужно перевести на микросервисную архитектуру (хотя бы в части открытия депозитов), чтобы обеспечить масштабируемость и совместимость с Kafka                                      | Текущий ASP.NET MVC 4.5 несовместим с Kafka. Возможен вынос нового функционала в отдельные сервисы                 |
| S6  | Обеспечить логирование всех операций с заявками, ставками, скорингом для аудита и расследования инцидентов                                                                                       |                                                                                                                    |
| S7  | Система должна предоставлять метрики и мониторинг (время ответа, ошибки, загрузка БД, количество заявок в очереди)                                                                               |                                                                                                                    |
| +R  | + Ограничения (Restrictions)                                                                                                                                                                     |                                                                                                                    |
| +R1 | Прямая работа интернет-банка с API АБС запрещена из-за перегруженности БД АБС                                                                                                                    | Следует использовать буфер (очередь/БД) или промежуточный сервис                                                   |
| +R2 | Система скоринга не должна использоваться для предрасчётов предодобренных предложений в реальном времени (только по инициативе клиента или асинхронно)                                           | Следует избежать дополнительной нагрузки в часы пик                                                                |
| +R3 | Интернет-банк сейчас не отказоустойчив – требуется переработка архитектуры (кластеризация, репликация, балансировка)                                                                             | Это архитектурно значимое требование для достижения 99,9%                                                          |
| +R4 | Все коммуникации между клиентом и системами должны быть зашифрованы                                                                                                                              | Защита персональных данных                                                                                         |
| +R5 | При доработках необходимо использовать технологии, совместимые с существующими платформами                                                                                                       |                                                                                                                    |
| +R6 | Бизнес-процессы должны быть реализованы с учётом возможности работы в двух ЦОД                                                                                                                   |                                                                                                                    |
| +R7 | Новый функционал не должен нарушать работу существующих операций в АБС                                                                                                                           |                                                                                                                    |
| +R8 | Новые клиенты обязаны пройти идентификацию в отделении с предъявлением документов                                                                                                                |                                                                                                                    |
| +R9 | Доступ к персональным данным клиентов разграничен по ролям (сотрудник кол-центра,сотрудник фронт-офиса, IT-специалисты, бэк-офис – депозитное и с кредитное управление)                          |                                                                                                                    |
